# 브리프 — 호흡기 질환 진료비 격차 대시보드
상태: 1차 대시보드 구현 완료 · 수정일: 2026-10-21

## 목적 (어떤 결정을 돕는가)
소득 수준과 의료기관 종별·권역에 따라 진료비가 달라지는지를 정기적으로 확인한다. 특히 호흡기 질환(J00~J99)을 깊게 본다.
"빈부격차 때문에 병원별 진료비 차이가 난다"는 가설을 데이터로 **검증하는 도구**이지, 결론을 미리 정해 두지 않는다.

## 사용자와 사용 맥락
- 1차: 작성자 본인(보건의료분석담당) — 월 단위 모니터링과 보고
- 2차: 상사·팀 보고
- 3차: 일반 배포 → 설명, 출처, 한계 표기가 필수
- 갱신: 수동(새 데이터가 오면 스크립트를 한 번 실행해 JSON 재생성)

## 확정된 정의
| 항목 | 결정 |
|---|---|
| 비교 단위 | 요양기관 종별 × 권역 (기관 이름은 데이터에 없음) |
| 소득 대리변수 | 건강보험료 5분위 (의료급여는 분위가 없어 별도 그룹으로 표기) |
| 질환 범위 | 호흡기 J00~J99 전체, 세부 상병별 드릴다운 |
| 감염병 | 호흡기만 본다. 감염성 상병(폐렴, 독감 등)은 표시 태그로 구분 |
| 비용 지표 | 명세서당 총진료비 (`rvd_rpe_tamt_amt`) |
| 시간 축 | 월별 추이 (2024~2025, 약 24개월) |
| 보정 | 입원(021)/외래(031) 분리 + 같은 상병 안에서만 비교 (연령·성별 표준화는 안 함) |
| 형태 | 정적 웹페이지 (HTML + JSON) |
| 데이터 표기 | 가상(합성) 데이터임을 각 화면 상단에 상시 표기 |

## 지표 (차트 1개 = 1줄) — 초안
| 지표 | 정의 | 데이터 파일 | 차트 종류 |
|---|---|---|---|
| 호흡기 명세서 규모 | 월별 호흡기 명세서 수 | (미정) | 선 |
| 소득 5분위별 진료비 | 분위 × 서식(입원/외래) 명세서당 평균·중앙값 진료비 | (미정) | 막대 |
| 종별 × 권역 진료비 | 종별 × 권역 평균 진료비 | (미정) | 히트맵 |
| 상병별 격차 | 상위 호흡기 상병의 5분위 간 진료비 비 (5분위 / 1분위) | (미정) | 표/막대 |
| 월별 격차 추이 | 월별 1분위 대비 5분위 진료비 비 | (미정) | 선 |

## 필터 / 비교 축
기간, 서식(입원/외래), 상병(J 코드), 종별, 권역, 소득 5분위(의료급여 포함)

## 데이터 범위와 한계 (화면에 표기할 것)
- 명세서·수진자·요양기관은 **가상 데이터**, 상병마스터와 코드표만 심평원 공개 자료
- 환자 3,000명, 명세서 38,375건 → 상병·종별·권역을 교차하면 셀이 작아져 불안정함 (최소 건수 기준 필요)
- 요양기관 이름이 없어 개별 병원 비교는 불가
- 소득 5분위는 보험료 기준 대리변수이고, 의료급여 대상자는 분위가 비어 있음
- 연령·성별은 보정하지 않으므로 인과가 아닌 **관찰된 차이**로 표현

## 제약 (기술, 갱신 주기, 배포)
정적 HTML, 수동 갱신, 서버 없음, 일반 배포 가능 형태

## 열린 질문 (다음 인터뷰)
- 최소 표시 건수 기준(예: n<30이면 "표본 부족")
- 격차를 하나의 대표 숫자(예: 5분위/1분위 비)로 요약할지
- 차트 라이브러리 선호 / 디자인 레퍼런스 / 배포 위치
- 합성 데이터에서 격차가 실제로 나타나는지 확인한 뒤 화면 메시지를 정함

## 구현 결과 (1차)
- 가설("소득 격차 때문에 진료비가 다르다")은 **지지되지 않았고**, 그 결과를 그대로 화면에 담았다. 소득 5분위 ÷ 1분위 = 0.99배, 같은 상병 기준으로도 방향성 없음.
- 격차는 **종별**에서 나타난다 (상급종합 ÷ 의원 ≈ 3.0배).
- 감염성 = ICD J00~J22 로 정의했다 (급성 호흡기 감염, 독감, 폐렴).
- 표본 기준: 한 칸 30건 미만은 "표본 부족"으로 표시.
- 호흡기 입원 명세서는 53건뿐이라 분석에서 제외.
- 열린 질문 중 "최소 건수 기준"은 30건으로 정했다. 나머지(대표 숫자, 디자인 레퍼런스, 배포 위치)는 남아 있음.

## 갱신 방법
```powershell
powershell -ExecutionPolicy Bypass -File data\build-data.ps1 -SourceDir "<SQL 덤프 폴더>"
```
그 뒤 `web/index.html` 을 브라우저로 열면 된다. (`data/dashboard-data.js` 가 새로 만들어진다.)
